==============================================================================
 一、数据结构变更
==============================================================================

 struct dfs_ext4_file 新增 4 个字段:

   uint8_t *rw_buffer;      // 动态分配, NULL = 回退直接 I/O
   off_t    rw_buf_pos;      // 缓冲区在文件中的起始偏移
   size_t   rw_buf_len;      // 缓冲区有效数据长度
   int      rw_buf_dirty;    // 1 = 有未刷盘的脏数据

 缓冲区内存在 dfs_ext_open 时分配, dfs_ext_close(ref_count==1) 时释放。

==============================================================================
 二、新增辅助函数
==============================================================================

 static int flush_dirty_buffer(struct dfs_ext4_file *ext_file)

   若 rw_buf_dirty == 0 或 rw_buf_len == 0, 直接返回 0。
   否则: ext4_fseek → ext4_fwrite(缓冲区全部数据) → 成功清零 dirty/len。
   失败返回 -EIO, 保留 dirty 标记供下次重试。

==============================================================================
 四、各函数详细逻辑
==============================================================================

 [1] dfs_ext_open — 缓冲区分配
 ─────────────────────────────
 首次打开常规文件 (ext4_fopen2 成功后):
   rw_buffer = rt_malloc(4096)
   成功 → rw_buf_pos=0, rw_buf_len=0, rw_buf_dirty=0
   失败 → rw_buffer = NULL (回退直接 I/O)

 重新打开 (type != EXT4_DE_UNKNOWN):
   常规文件 → 共享已有缓冲区; 若为 NULL 则尝试分配
   目录     → 新副本, 强制 rw_buffer = NULL

 [2] dfs_ext_read — 缓冲读
 ─────────────────────────────
 rw_buffer == NULL?
   ├─ 是 → 回退: ext4_fseek + ext4_fread 直接读
   └─ 否 → 缓冲读:
         while (count > 0 && pos < vnode->size)
         {
           if (pos 在 [rw_buf_pos, rw_buf_pos+rw_buf_len) 内)
           {
             memcpy 命中数据; pos += chunk; count -= chunk
           }
           else
           {
             if (dirty) flush_dirty_buffer()
             ext4_fseek → ext4_fread(4KB) → 填充缓冲
             rw_buf_pos=pos; rw_buf_len=rd; rw_buf_dirty=0
           }
         }

 关键场景:
   - 首次读 pos=0, 100B      → 读 4KB 填充, 拷贝 100B (1 次磁盘读)
   - 紧接着读 pos=100, 200B  → 缓冲命中, 直接 memcpy (0 次磁盘读)
   - 读位在脏缓冲内          → 直接从脏缓冲返回 (读己写, 0 次 I/O)
   - 读位不在脏缓冲内        → 先刷脏, 再读 4KB (1 写 + 1 读)

 [3] dfs_ext_write — 缓冲写
 ─────────────────────────────
 rw_buffer == NULL?
   ├─ 是 → 回退: ext4_fseek + ext4_fwrite 直接写
   └─ 否 → 缓冲写:
         while (count > 0)
         {
           if (脏 && 有空间 && pos == rw_buf_pos + rw_buf_len)
           {
             memcpy 追加到缓冲尾部
             若缓冲满 → flush_dirty_buffer()
           }
           else
           {
             if (脏) flush_dirty_buffer()   // 不连续,先刷旧缓冲
             if (count >= 4096)             // 大写入绕过缓冲
               ext4_fwrite 直接写盘
             else                           // 小写入新建缓冲
               memcpy → rw_buf_dirty=1
           }
         }
         if (*pos > vnode->size) vnode->size = *pos

 关键场景:
   - 64次 × 64B 连续写入    → 合并为 1 次刷盘 (合并比 64:1)
   - 5000B 大块写入         → 绕过缓冲, 直接写盘
   - pos=0写100B→pos=50写50B → 先刷[0,99]再缓冲[50,99] (1 次写)
   - pos=0写100B→pos=100写50B → 追加同一缓冲 (0 次写)

 [4] dfs_ext_flush — 显式刷盘
 ─────────────────────────────
 若 rw_buf_dirty → flush_dirty_buffer()
 然后 ext4_cache_flush()

 [5] dfs_ext_lseek — 跳离脏区刷盘
 ─────────────────────────────
 generic_dfs_lseek 计算 ret 后:
   若 ret < rw_buf_pos 或 ret > rw_buf_pos + rw_buf_len
   → flush_dirty_buffer() (跳出脏缓冲范围)
   否则不刷盘 (仍在缓冲范围内或紧邻末尾)

 场景:
   write(0,100) → lseek(5000)  → 刷 ✅  (5000 > 100)
   write(0,100) → lseek(50)    → 不刷   (50 在 [0,100) 内)
   write(0,100) → lseek(100)   → 不刷   (紧邻末尾, 可追加)
   read(0,100)  → lseek(2000)  → 不刷   (无脏数据)

 [6] dfs_ext_close — 释放缓冲区
 ─────────────────────────────
 ref_count > 1 → 立即返回 (还有其他句柄)
 ref_count == 1:
   若 dirty → flush_dirty_buffer()
   rt_free(rw_buffer), rw_buffer = NULL
   然后 ext4_fclose / ext4_dir_close

 [7] dfs_ext_truncate — 截断失效缓冲
 ─────────────────────────────
 ext4_ftruncate 后:
   rw_buf_len = 0; rw_buf_dirty = 0

 [8] dfs_ext_page_write — 页缓存一致性
 ─────────────────────────────
 direct ext4_fwrite 前:
   若 dirty → flush_dirty_buffer() (保证数据一致性)

==============================================================================
 六、错误处理
==============================================================================

 内存分配失败:
   rt_malloc → NULL → rw_buffer = NULL → 读写走回退路径 (直接 I/O)
   → 功能不受影响, 仅性能退化

 磁盘 I/O 失败:
   - 读缓冲填充失败 → break 退出, 返回已读字节
   - 写缓冲刷盘失败 → goto write_out, 保留 dirty 标记
   - lseek 刷盘失败  → 保留 dirty, 下次操作重试
   - flush 刷盘失败  → 立即返回错误码, 保留 dirty

 截断:
   ftruncate → 清空 rw_buf_len + rw_buf_dirty (废弃缓冲内容)

==============================================================================
 七、性能模型
==============================================================================

 小顺序写入 (64 × 64B = 4096B):
   无缓冲: 64 次 ext4_fwrite
   有缓冲: 1  次 ext4_fwrite
   合并比: 64:1

 小顺序读取 (32 × 128B = 4096B):
   无缓冲: 32 次 ext4_fread
   有缓冲: 1  次 ext4_fread (首次 4KB) + 31 次 memcpy
   磁盘 I/O 减少: 97%

 折衷:
   收益: 减少函数调用、减少锁操作、缓冲命中零延迟
   代价: 每个打开文件 4KB 内存、lseek 跳离时额外刷盘
   风险: 崩溃丢失未刷盘脏数据 (最多 4KB)

==============================================================================
 八、线程安全
==============================================================================

 所有缓冲操作在 vnode->lock 保护下执行 (RT-Thread 递归互斥锁)。
 ref_count 确保最后一个句柄关闭时才释放缓冲区, 防止 use-after-free。
 多句柄共享缓冲区: 任一句柄的 I/O 影响共享缓冲状态 (见设计文档第7/8章)。
